# V2 carrier timing firmware review

Implementation lives in `/workspace/working-source/thesi_power_control.ino`. Tests are `firmware/test_web_protocol.py` and new `firmware/test_carrier_storage.py`. The selected `/workspace/Thesis` reference checkout is unchanged. No board was opened or flashed; no commit, push, deployment, or publication occurred.

## Protocol and timing

- F410 / V2 is PWR-2.0.4 (numeric patch 4). G071 retains PWR-2.0.3, nominal 1 MHz / 40 ns and its prior timing implementation, with numeric patch corrected to 3.
- F410 alone advertises `carrier_timing_v1`. Browser command: `WEB <id> TIMING <integer Hz> <integer ns>`. Native terminal: `TIMING <Hz> <ns>` to apply, `TIMING` to read the exact fractions.
- Numerical bench bounds are 500000..2000000 Hz and 20..200 ns. These are software bounds, not an established electrical safe operating range. A valid pair must also satisfy linear DTG 1..127 and `4 * dead_ticks < period_ticks`.
- V2 now uses edge-aligned complementary CH1/CH1N, PA8/PB13, CH2 disabled for PA9 UART. `period_ticks = 2 * floor((timer_hz + requested_hz) / (2 * requested_hz))`, ARR = period_ticks - 1, CCR1 = period_ticks / 2, RCR = 0, PSC = 0, CMS = 0. Ties choose the longer even period. Dead ticks are rounded up from requested nanoseconds. The default steady carrier remains 1 MHz / 40 ns at the standard 100 MHz timer clock. The startup edge phase changes from the earlier center-aligned implementation and requires scope verification.
- All F410 gate cycle/time conversions use the exact timer clock / period-tick fraction, including minimum bursts and pulse skipping. They do not use a rounded displayed frequency.
- Application requires OFF and no startup, autotune, or queued/running calibration. It rechecks those conditions under the interrupt lock, forces EN low, disables MOE/CEN, writes the coupled pair, triggers UG and clears status, verifies readback, recomputes the EN scheduler, and resumes the existing carrier while EN stays low. The prior interrupt mask is preserved. Failure leaves EN/MOE/CEN off and latches a fault. It never enables the power output or clears a preexisting fault.
- Effective period/dead-tick changes clear the three learned load-profile records and tuned metadata, retaining physical LOAD resistances, applied duty settings, protection limits and sensor calibration. They also clear the prior browser calibration completion result. Changes that quantize to the same actual pair preserve learned metadata. Production LOAD validation rejects the cleared profiles.
- Dedicated `type: timing` JSON frames report requested/actual rounded integers, exact timer_hz/period_ticks/dead_ticks, bounds, revision, enabled and busy. They are sent after SNAPSHOT, successful TIMING and each streamed telemetry sample. SNAPSHOT and TIMING frames carry the request ID; streamed timing uses an empty ID. Exact frequency is timer_hz / period_ticks; exact dead time in ns is dead_ticks * 1e9 / timer_hz. `actual_hz` is nearest integer; `actual_dead_ns` is rounded upward.
- A successful browser TIMING remains pending in RAM until explicit SAVE/ENDCFG. Native terminal settings retain the existing quiet-OFF 1.5 second deferred-save policy, except while BEGINCFG is active. Other existing terminal saves persist timing and settings coherently.

## Journal compatibility

The immutable legacy packed SettingsSlot is **471 bytes**, in a **472 byte old stride**. New F410 records have a distinct four-byte prefix, the unchanged 471-byte legacy payload with its inner checksum, one new reserved 0xFF alignment byte, requested Hz, requested ns, and an outer checksum: **488 bytes total**, 33 complete records in the 16 KiB settings sector.

The loader scans legacy 472-byte and new 488-byte layouts, selects the highest sequence, and prefers the new wrapper at equal sequence. Legacy loading adopts the 1 MHz / 40 ns defaults without writing or erasing flash. Both checksums, prefix, reserved byte and timing pair are validated before a new record is accepted. The prefix keeps a corrupt extension from being mistaken for a legacy record. The append cursor reserves every occupied new-stride block, including old records or torn records whose first word is erased. The writer checks every word of an append region before programming it. Timing and calibration are saved together in one checksummed record.

Journal wrap still erases the single sector only during an allowed OFF-state save. As before, a power failure during that sector erase/wrap can lose the journal; these tests do not claim hardware power-loss immunity. Boot migration never erases or saves.

## Validation

- `python3 /workspace/tooling/test-working-protocol-linux.py`: PASS, running the assertions and extracted production code from `firmware/test_web_protocol.py` with native GCC. Covers the production dispatcher, pure timing math, actual EN scheduling, actual pair application, and production load-profile validity/application. Includes malformed/range/coupled-pair requests, 34390 timing-pair attempts, exact rational conversions, busy/OFF/lease interlocks, IRQ-mask preservation and locked-state recheck, simulated timer readback failure, profile invalidation, no automatic output enabling, congestion, streaming and bounded serialization. The runner now supports native GCC/Clang directly, and the compatibility helper delegates to it. The retained Windows/MSVC branch was not executed here.
- `python3 firmware/test_carrier_storage.py`: PASS, production flash reader/writer, checksums, loader, saver and save guards using native HAL flash stubs. Verifies byte-exact legacy calibration migration, no boot write/erase, coherent calibration/timing reboot, newest/equal-sequence selection, corrupt inner/outer/pair rejection, full-region occupancy and all 122 interrupted append-word boundaries, full legacy/new journal wrap and OFF/startup/autotune/calibration/storage guards. Unrelated settings validation/defaults and physical flash are mocked.
- `bash /workspace/tooling/build-working-firmware.sh F410`: PASS. Flash **90268 / 98304 bytes**, RAM **6868 / 32768 bytes**. HEX verifier: **90752 programmed bytes**, settings sector 0x08004000..0x08007FFF excluded.
- `bash /workspace/tooling/build-working-firmware.sh G071`: PASS. Flash **130424 / 131072 bytes**, RAM **9544 / 32768 bytes**. Existing 648-byte flash headroom preserved.
- Stressed protocol run: 131 JSON frames; largest serialized telemetry **913 bytes**, timing **350 bytes**, below 1024 bytes. The timing stress includes a 24-character request ID and maximum uint32 millisecond/revision values. Periodic telemetry/timing pairs are queued only into an empty queue, preserving two reply/event slots. Emergency OFF remains effective during TX congestion.

Logs: `f410-build.log`, `g071-build.log`, `protocol-tests.log`, `storage-tests.log`; serialized evidence: `protocol-frames.jsonl`, `protocol-frame-budgets.json` in this directory. Both native suites passed after the final source changes. Target builds cover the final firmware source. No physical PWM, driver non-overlap, electrical limits, startup behavior or flash programming has been verified on a board.
